Keep only outstanding items here: remove an item when it is done, and delete `TODO.md` when nothing remains.

Decide on a brief intro and optional About/Projects navigation without losing the minimal aesthetic.

This makes publishing in the open reproducible.

### Visual direction: readable, accessible, still nerdy

- [ ] **Offer an optional reading-font switch without changing the default personality.** Keep system monospace as the default everywhere; let readers switch long-form prose to a proportional system UI font while keeping code, dates, and site identity monospace. Do not download fonts. Make the control labeled, keyboard accessible, and persistent across pages (with a sensible no-JavaScript default); test both modes on desktop and phone. Keep comfortable line height, roughly 65–75ch for prose, and scrolling for wide code/tables.
- [ ] **Strengthen keyboard and touch affordances.** Add visible `:focus-visible` outlines to links, increase small footer-nav tap targets, and review link states. Check keyboard navigation and zoom, not just colors.
- [ ] **Fix the external-link annotation.** The CSS-generated `[ext]` marker in `assets/css/main.css` uses muted `#928374` on `#282828` (about 4:1 contrast), and generated text is not reliable accessible labeling. Use a higher-contrast treatment and meaningful link text; avoid marking links to the site's own domain as external.
- [ ] **Try Gruvbox dark hard as a small visual experiment, not a wholesale redesign.** Compare `#1d2021` against the current `#282828` background on real posts in daylight and at night; if adopted, change the code-block/blockquote surfaces so they remain distinguishable and sync `theme-color` plus `static/site.webmanifest`. Check contrast and reading comfort at normal text sizes.
- [ ] **Explore useful nerdy details without making the page a fake terminal.** Prototype one or two of: protocol-inspired section labels, a dated project/experiment log, small changelog or git links, and code examples with clear copy/permalink controls. Keep headings semantic, information readable without JavaScript, and decorative ASCII out of the accessibility tree.
- [ ] **Prototype sidenotes / marginalia for longer posts.** Use [Tufte CSS](https://edwardtufte.github.io/tufte-css/) as a design reference, not a wholesale dependency: put short annotations or footnotes in the outer margin on wide screens (left or right); keep them inline or as linked endnotes on narrow screens and in a logical reading order for screen readers. Use comfortably sized system text (e.g. ~0.875rem, not tiny), keyboard-friendly reference/back links, and avoid collisions with images and code.
- [ ] **Try a pencil-sketch notebook motif without a font download.** Use system UI and system monospace stacks; commission or draw a small original hand-sketched portrait/icon and a few restrained pencil-like marks (SVG or compressed image). Give meaningful images alt text, hide purely decorative strokes from assistive tech, and avoid imitating another person's portrait.
- [ ] **Experiment with quiet notebook borders.** Try CSS-only top/bottom rules, imperfect-looking strokes, or a tiny static texture rather than a continuously animated canvas. If motion is tried, respect `prefers-reduced-motion`, avoid layout shifts, and measure its cost on mobile.
- [ ] **Offer a real Markdown view for each post.** Inspired by [Armin's post](https://lucumr.pocoo.org/2026/9/12/pdoom/): serve usable Markdown at a stable URL and link `View Markdown` in HTML; optionally add `Copy as Markdown` with a small progressive-enhancement script. Check how Hugo shortcodes and internal links appear in the exported text, and reconcile any script with the site's CSP (`script-src 'none'` is currently declared in `static/_headers`).

First decide if this is an actual paid-service offer or an invitation to collaborate; keep the site's writing front and center rather than copying a consulting landing page.
